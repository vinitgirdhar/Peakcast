# Zero-ambiguity rule linter

**Recommendation.** Put a pure, deterministic `lintDraft(draft, now)` in `shared/lint.ts`, so the Draft studio runs it live as the creator types and the server runs the same code at launch, the way quotes and trades share one LMSR function. Launch is **blocked only by deterministic `block` findings**: problems that make a market unresolvable or manipulable, such as a comparison with no number, a URL shortener, a creator-as-judge rule or identical rules. `warn` findings need a checkbox in the studio and are **published on the market** as a rule-check summary, so traders can see them. The API does not demand an acknowledgement flag, so existing clients and tests keep working.

An optional AI critique reuses the existing provider adapters in `server/ai.ts` with a schema-validated, advisory-only output. It can never block, launch or edit anything. The server never fetches or resolves source URLs. One implementer, about 6 dev-days.

Status: plan for batch 2, written 2026-11-22 against `main` at `4a021de`.

## Deterministic checks

All of these are text and URL rules over the seven `DraftInput` fields: word lists, regular expressions and small static host tables in `shared/lint-data.ts`. Every finding carries the `field` it points at and the matched text, so the UI can highlight it.

| Id                          | Severity                            | Fires when                                                                                                                                                                                                                                                                                                |
| --------------------------- | ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `comparator-without-number` | **block**                           | The question or YES rule uses a comparison word (above, below, over, under, exceed, more/less than, at least/most, reach, hit, surpass, higher, lower, rise, fall) and neither contains a number                                                                                                          |
| `rules-identical`           | **block**                           | Any two of YES, NO and INVALID are equal after lower-casing and collapsing whitespace and punctuation                                                                                                                                                                                                     |
| `subjective-judge`          | **block**                           | A rule makes a person the judge: "in the (creator's\|our\|my) opinion", "at the discretion of", "as determined by the creator", "I/we will decide". The creator is also the proposer in `propose()`.                                                                                                      |
| `url-shortener`             | **block**                           | Source host is a known shortener (bit.ly, t.co, tinyurl.com, goo.gl, ow.ly, is.gd, buff.ly, cutt.ly, rb.gy): it can redirect anywhere later                                                                                                                                                               |
| `url-not-public-host`       | **block**                           | The host is an IP literal, `localhost`, single-label, or `.local`, `.internal`, `.lan` or `.home.arpa`                                                                                                                                                                                                    |
| `closes-too-soon`           | **block**                           | `closesAt` is less than 1 hour after `now`                                                                                                                                                                                                                                                                |
| `threshold-boundary`        | warn                                | In the question or YES rule, a number sits next to above/below/over/under/exceed/more than/less than, and neither has boundary wording (at least, at most, or more, or higher, strictly, inclusive, ≥, ≤, equal to): "Say whether exactly X counts." The NO rule is the complement, so it is not checked. |
| `rule-gap`                  | warn                                | After outcome labels ("Resolves NO", "NO:") are stripped, the NO rule has no catch-all or negation (otherwise, any other, any value, anything else, not, n't, no, none, never, fails), so a result that matches neither rule is not covered                                                               |
| `vague-term`                | warn in rules, info in the question | Words from a list: significant(ly), substantial(ly), major, widely, roughly, approximately, around, about, soon, recently, many, several, few, popular, successful, credible, reputable, mainstream, considerable, notable, may, might, could                                                             |
| `event-date-missing`        | warn                                | No date or period can be parsed from the question or YES rule (ISO dates, "Month D, YYYY", "D Month YYYY", "Month YYYY", "Q1–Q4 YYYY", "in/during/by/before/end of YYYY")                                                                                                                                 |
| `date-without-year`         | warn                                | A month name or "end of the month/quarter" appears in the question with no year anywhere in the question or YES rule                                                                                                                                                                                      |
| `timezone-missing`          | warn                                | A day-level date or clock time (17:00, 5 pm, midnight, noon, end of day, market close) appears with no zone (UTC, GMT, IST, ET/EST/EDT, PT, CET, Z, ±hh:mm, "local time in …"). Bare years and months only produce info.                                                                                  |
| `close-after-event`         | warn                                | `closesAt` is later than the parsed event end plus the source's publication lag (lag table), or plus 1 day for unknown sources: the outcome may be public while trading is still open                                                                                                                     |
| `no-publication-deadline`   | warn                                | The INVALID rule names no date or duration ("by <date>", "within N days") after which a missing publication counts                                                                                                                                                                                        |
| `outage-unhandled`          | warn                                | The INVALID rule does not mention the source being unavailable, not published, discontinued, delayed, missing or offline (matched by stem, so "does not publish" and "discontinues" count)                                                                                                                |
| `revision-unspecified`      | warn                                | The source is flagged as revisable in the lag table, or the rules say estimate/preliminary/advance/flash/provisional, and no rule names the vintage ("first release", "as first published", "initial", "revisions do not")                                                                                |
| `postponement-unhandled`    | warn                                | The question names a scheduled event (match, game, election, vote, launch, meeting, IPO, flight, ceremony) and no rule says postponed, cancelled, delayed, rescheduled or abandoned                                                                                                                       |
| `multiple-sources`          | warn                                | A rule names alternatives ("X or Y reports", "and/or", "any major outlet", "news reports")                                                                                                                                                                                                                |
| `source-not-in-rule`        | warn                                | The YES rule mentions neither a significant word of `sourceName` (3 or more letters, stop words removed) nor the source host's main label (`bls` for `www.bls.gov`)                                                                                                                                       |
| `self-reference`            | warn                                | Rules depend on Peakcast itself: "this market", "on Peakcast", "trading volume", "the market probability"                                                                                                                                                                                                 |
| `question-not-binary`       | warn                                | The question does not start with Will/Is/Does/Has/Did/Are/Was/Can, starts with which/who/what/how many, or offers "A or B"                                                                                                                                                                                |
| `url-placeholder`           | warn                                | `example.com/.org/.net`, or a `.example`, `.test` or `.invalid` host. This is a warning, not a block, because the existing tests and e2e fixtures launch drafts with `https://example.org/data`.                                                                                                          |
| `url-social`                | warn                                | x.com, twitter.com, facebook.com, instagram.com, reddit.com, t.me, youtube.com, tiktok.com, linkedin.com: posts are not primary records                                                                                                                                                                   |
| `url-search-page`           | warn                                | A search-engine host with `/search` or a `q=` parameter                                                                                                                                                                                                                                                   |
| `url-secret-param`          | warn                                | Query parameter names such as token, key, sig, signature, auth, session or password                                                                                                                                                                                                                       |
| `closes-too-far`            | warn                                | `closesAt` is more than 2 years after `now`                                                                                                                                                                                                                                                               |
| `publication-lag`           | info                                | A known-lag source: "Expect the figure about N days after the period ends; resolution waits for it."                                                                                                                                                                                                      |
| `close-before-event`        | info                                | Trading closes more than 7 days before the parsed event end                                                                                                                                                                                                                                               |
| `invalid-refund-wording`    | info                                | The INVALID rule says "refund", but INVALID pays 0.5 credit per share on both sides (`payOut` in `server/resolution.ts`)                                                                                                                                                                                  |
| `source-host-mismatch`      | info                                | `sourceName` names a known agency in the host table, but the URL's host is different                                                                                                                                                                                                                      |

### Score and gate

`risk = min(100, 40·blocks + 12·warnings + 3·infos)`. The label is **Blocked** for any block, **Review** at 15 or more, and **Clear** below 15.

| Result              | Draft studio                                                | `POST /drafts/:id/launch`                                                                                                         | Market rules view                             |
| ------------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| One or more blocks  | Launch disabled; blocking findings listed first             | **409** `"Fix 2 blocking rule problems before launch: rules-identical, url-shortener."`. Rolled back: draft kept, no stake taken. | —                                             |
| Warnings, no blocks | Launch requires "I reviewed these N warnings" (client-side) | 201; `definition.ruleCheck = {risk, warnings: ["threshold-boundary", …]}` stored in the market's definition JSON (no migration)   | "Launched with 2 unresolved warnings", listed |
| Info only, or clean | Launch                                                      | 201, with `ruleCheck` stored                                                                                                      | "Rule check: clear"                           |

Lint runs after the existing "closing time has passed" check in `launchDraft`, so that message and its test (`launch refuses expired deadlines…` in `tests/api.test.ts`) stay unchanged. Seed fixtures never pass through `launchDraft`, so they are not gated, and older markets have no `ruleCheck`.

### Source URL policy (no server fetching)

- The server never fetches, resolves or pings `sourceUrl`. Fetching would turn `/api/v1` into a server-side request forgery primitive against Render's internal network and the desktop's loopback. All URL checks above are structural and work on `new URL()` output only.
- Reachability is a human check. The launch panel shows the source as a link (`target="_blank" rel="noopener noreferrer"`) and the warning checklist includes "I opened the source and it shows the figure the rules name." This is a nudge, not a control, and the docs say so.
- Windows: `desktop/main.mjs` only opens external links that match a launched market's `sourceUrl` or evidence link, so a draft's source link is denied there. On desktop, the studio offers **Copy link** instead (the clipboard permission is already granted to the app origin).
- Later (not in this plan): an allowlisted fetcher for a fixed set of official hosts, run in a separate worker.

## Optional AI critique

| Aspect                      | Design                                                                                                                                                                                                                                                                                                                                                                           |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Route                       | `POST /api/v1/drafts/critique?provider=` with body `DraftSchema`. Bearer plus `X-AI-Access-Token`, the same checks as `/drafts/generate`; rate limit 3/minute; 503 when unconfigured, 403 for a bad token, 502 for invalid output. Stateless: nothing is saved.                                                                                                                  |
| Adapter                     | Extract `requestStructured(selected, instructions, input: unknown, schema, name): Promise<string \| undefined>` from `generateDraft`, covering the Ollama, Gemini, Groq and OpenAI branches. `generateDraft` keeps its behaviour, and `tests/ai.test.ts` and `tests/providers.test.ts` must pass unchanged as the refactor's regression guard.                                   |
| Prompt                      | The submitted draft JSON plus the deterministic finding ids, both marked as untrusted data. Instructions: point out remaining ambiguity, do not repeat the listed ids, do not rewrite the draft, do not claim to have checked the source.                                                                                                                                        |
| Schema sent to the provider | `{summary: string, findings: [{field: enum of the 7 DraftInput keys, severity: "warn" \| "info", message: string, suggestion: string, quote: string}]}`. Only `type`, `properties`, `required`, `additionalProperties: false` and `enum` are used, so the same object works with OpenAI and Groq strict mode, Gemini `responseJsonSchema` and Ollama `format`.                   |
| Server validation           | A TypeBox `CritiqueSchema` checked after parsing: summary ≤ 400 characters, at most 8 findings, message and suggestion ≤ 300, quote ≤ 200. **Each `quote` must appear verbatim (case-insensitive) in the field it names, or that finding is dropped.** There is no `block` severity, so the model cannot gate a launch. Malformed output returns 502 and the draft is untouched. |
| Response                    | `{provider, summary, findings}`. The UI labels it "AI suggestion, advisory" and shows it apart from the deterministic findings.                                                                                                                                                                                                                                                  |
| Desktop                     | `desktop/main.mjs` adds `X-AI-Access-Token` only for `/api/v1/settings/` and `/api/v1/drafts/generate`. Add `/api/v1/drafts/critique`, or the managed desktop critique returns 403.                                                                                                                                                                                              |
| Errors                      | Add `/drafts/critique` to the `onRoute` error-code list in `server/app.ts` (502, 503), next to `/drafts/generate`.                                                                                                                                                                                                                                                               |

## Types

```ts
// shared/lint.ts
export type LintSeverity = "block" | "warn" | "info";
export type LintField = keyof DraftInput;
export interface LintFinding { id: string; severity: LintSeverity; field: LintField; message: string; match?: string }
export interface LintReport { risk: number; label: "Blocked" | "Review" | "Clear"; findings: LintFinding[] }
export function lintDraft(draft: DraftInput, now?: number): LintReport; // pure; never throws on schema-valid input

// shared/types.ts
export interface RuleCheck { risk: number; warnings: string[] }
// MarketDefinition += ruleCheck?: RuleCheck   (MarketSchema += optional object)
export interface DraftCritique { provider: AIProvider; summary: string; findings: (Omit<LintFinding, "id" | "severity"> & { severity: "warn" | "info"; suggestion: string; quote: string })[] }

// shared/client.ts
critiqueDraft(input: DraftInput, aiAccessToken: string, provider?: AIProvider): Promise<DraftCritique>;
```

## UI

- **Rule check panel** (new `src/pages/RuleCheck.tsx`, which keeps `DraftStudio.tsx` well under 800 lines). It is debounced by 300 ms over the current form, with `closesAt` taken from the `datetime-local` value. It shows a risk badge, then findings grouped by block, warn and info, each with its field label and matched text. Clicking a finding focuses its field. An `aria-live="polite"` region announces only the counts.
- **Saved drafts.** Each draft shows a badge. Launch is disabled with the reason when the draft is blocked. When it has warnings, a checkbox and the "I opened the source" confirmation are required. **Edit as new draft** loads the draft into the create form (the same mechanism as `fillExample`).
- **Ask AI for a critique** appears only when `capabilities.aiConfigured`. It uses the provider and access-token inputs the form already has.
- **Market rules view** shows the `ruleCheck` line.

## Acceptance criteria

1. `lintDraft` is pure, lives in `shared/`, and the UI and server import the same function. No network or DNS access anywhere in the linter (code review plus a test that stubs `fetch` to throw).
2. Every case in the table passes. Seed fixtures and the existing test drafts produce zero blocks, and `npm run verify` passes with the 80% coverage gate.
3. Launching a blocked draft returns 409 with the check ids and changes nothing. Warnings never fail the API launch and are stored and shown on the market.
4. The AI critique is advisory only, validated by `CritiqueSchema` plus the verbatim-quote rule, never persisted, and gated exactly like `/drafts/generate`. The existing AI tests pass unchanged after the adapter refactor.
5. The studio shows findings live and accessibly, and Windows shows Copy link instead of a dead source link.
